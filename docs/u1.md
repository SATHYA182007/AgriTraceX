## DATABASE SCHEMA (Supabase Postgres + PostGIS)

```sql
-- Core
create table profiles (
  id uuid primary key references auth.users(id),
  full_name text,
  role text check (role in ('farmer','field_officer','government','insurance','super_admin')),
  district text,
  phone text,
  avatar_url text
);

create table parcels (
  id uuid primary key default gen_random_uuid(),
  farmer_id uuid references profiles(id),
  name text,
  area_ha numeric,
  crop_type text,
  location geography(Point, 4326),
  boundary geography(Polygon, 4326),
  created_at timestamptz default now()
);

create table readings (
  id uuid primary key default gen_random_uuid(),
  parcel_id uuid references parcels(id),
  sensor_type text,
  value numeric,
  unit text,
  recorded_at timestamptz default now()
);

create table alerts (
  id uuid primary key default gen_random_uuid(),
  type text check (type in ('FLOOD','DROUGHT','PEST','FIRE','FROST')),
  severity text check (severity in ('LOW','MEDIUM','HIGH','CRITICAL')),
  parcel_id uuid references parcels(id),
  district text,
  description text,
  acknowledged boolean default false,
  created_at timestamptz default now()
);

create table extension_requests (
  id uuid primary key default gen_random_uuid(),
  farmer_id uuid references profiles(id),
  parcel_id uuid references parcels(id),
  alert_id uuid references alerts(id),
  requested_date date,
  photo_url text,
  status text check (status in ('PENDING','SCHEDULED','COMPLETED')) default 'PENDING',
  created_at timestamptz default now()
);

create table verifications (
  id uuid primary key default gen_random_uuid(),
  alert_id uuid references alerts(id),
  fo_user_id uuid references profiles(id),
  decision text check (decision in ('ACCEPT','REJECT')),
  corrected_crop_type text,
  corrected_risk_score numeric,
  notes text,
  photo_url text,
  verified_at timestamptz default now()
);

create table field_notes (
  id uuid primary key default gen_random_uuid(),
  parcel_id uuid references parcels(id),
  fo_user_id uuid references profiles(id),
  note text,
  photo_url text,
  created_at timestamptz default now()
);

create table reports (
  id uuid primary key default gen_random_uuid(),
  parcel_id uuid references parcels(id),
  generated_at timestamptz default now(),
  storage_path text,
  status text check (status in ('pending','verified','rejected')) default 'pending',
  ai_crop_type text,
  ai_risk_score numeric
);

create table government_actions (
  id uuid primary key default gen_random_uuid(),
  action text check (action in ('WATER_RELEASE','SUBSIDY_DISBURSE','PEST_SPRAY','RELIEF_FUND')),
  district text,
  target_parcel_ids uuid[],
  notes text,
  created_by uuid references profiles(id),
  created_at timestamptz default now()
);

create table claims (
  id uuid primary key default gen_random_uuid(),
  farmer_id uuid references profiles(id),
  parcel_id uuid references parcels(id),
  alert_id uuid references alerts(id),
  status text check (status in ('PENDING','UNDER_REVIEW','APPROVED','REJECTED')) default 'PENDING',
  claimed_amount numeric,
  payout_amount numeric,
  report_url text,
  created_at timestamptz default now()
);

create table model_versions (
  id uuid primary key default gen_random_uuid(),
  version_name text,
  accuracy numeric,
  deployed_at timestamptz default now(),
  is_current boolean default false
);

create table chat_messages (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references profiles(id),
  role text check (role in ('user','assistant')),
  content text,
  created_at timestamptz default now()
);
```

Enable Row-Level Security on all tables. Each role can only read/write rows appropriate to their function (farmers see only their parcels and claims; FOs see only their district's parcels and alerts; government sees district-level aggregates; insurance sees claims; super_admin sees everything).

## FLOATING CHATBOT (ALL ROLES)

Every dashboard has a floating AI assistant button in the bottom-right corner.

**Design:**
- Circular FAB button, 56px, with a wheat-stalk + chat-bubble icon
- On click: slides up a chat panel (380px wide, 500px tall) anchored to bottom-right
- Role-aware: the system prompt changes per role (see below)
- Uses the Anthropic API (`claude-sonnet-4-20250514`) via a Next.js API route `/api/chat`
- Chat history persisted in `chat_messages` table per user session
- Typing indicator (animated dots) while waiting for response
- Markdown rendering in assistant messages (react-markdown)

**System prompts per role:**

Farmer:
"You are AgriBot, a helpful agricultural assistant for Indian farmers. You know about the farmer's parcels, current alerts, and crop conditions. Help with: crop advice, understanding alerts, how to submit claims, irrigation scheduling, pest identification from photo descriptions, and government scheme eligibility. Always respond in simple English or ask if they prefer Hindi. Be warm and practical."

Field Officer:
"You are AgriBot, an assistant for Agricultural Field Officers in rural India. Help with: interpreting satellite NDVI data, writing verification notes, scheduling field visits, identifying crop diseases from descriptions, understanding soil moisture readings, and generating field report summaries. Be precise and technical."

Government Officer:
"You are AgriBot, a policy and relief coordination assistant. Help with: understanding district-level risk summaries, drafting relief action orders, interpreting analytics dashboards, eligibility rules for government schemes (PM-KISAN, PMFBY), and generating district briefing summaries from dashboard data."

Insurance Agent:
"You are AgriBot, an insurance claims assistant. Help with: evaluating claim validity based on FO verification notes, calculating fair payout amounts under PMFBY guidelines, drafting rejection or approval communications, understanding crop loss assessment methodology, and identifying fraudulent claim patterns."

Super Admin:
"You are AgriBot, the system administrator assistant for AgriSense. Help with: user management queries, understanding system health metrics, interpreting realtime event logs, debugging Supabase RLS policies, and explaining data flows between roles."

**API route (/api/chat):**
- Reads `profile.role` from session
- Picks the correct system prompt
- Sends conversation history from `chat_messages` table
- Streams response using Anthropic streaming API
- Saves both user message and assistant response to `chat_messages`

## REALTIME SUBSCRIPTIONS (per role)

Set up these Supabase realtime channel subscriptions on mount:

```javascript
// Farmer
supabase.channel('farmer-alerts')
  .on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'alerts', filter: `district=eq.${profile.district}` }, handleNewAlert)
  .on('postgres_changes', { event: 'UPDATE', schema: 'public', table: 'claims', filter: `farmer_id=eq.${userId}` }, handleClaimUpdate)
  .subscribe()

// Field Officer
supabase.channel('fo-dashboard')
  .on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'extension_requests', filter: `district=eq.${profile.district}` }, handleNewRequest)
  .on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'alerts', filter: `district=eq.${profile.district}` }, handleNewAlert)
  .subscribe()

// Government
supabase.channel('govt-dashboard')
  .on('postgres_changes', { event: 'UPDATE', schema: 'public', table: 'alerts' }, handleAlertUpdate)
  .on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'verifications' }, handleVerification)
  .subscribe()

// Insurance
supabase.channel('insurance-dashboard')
  .on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'claims' }, handleNewClaim)
  .on('postgres_changes', { event: 'UPDATE', schema: 'public', table: 'claims' }, handleClaimUpdate)
  .subscribe()

// Super Admin
supabase.channel('admin-firehose')
  .on('postgres_changes', { event: '*', schema: 'public', table: 'alerts' }, logEvent)
  .on('postgres_changes', { event: '*', schema: 'public', table: 'verifications' }, logEvent)
  .on('postgres_changes', { event: '*', schema: 'public', table: 'claims' }, logEvent)
  .subscribe()
```

All realtime events show a toast notification (top-right, role-accent colour) describing what changed.

## EDGE FUNCTIONS (Supabase Deno)

1. `process_satellite` — triggered on new image upload to `satellite-images/` bucket. Calculates NDVI, detects anomalies, inserts alert row if threshold breached.

2. `generate_report` — triggered on INSERT in `reports` table. Builds PDF using `pdfkit`, stores in `reports/` bucket, updates `reports.storage_path`.

3. `retrain_model` — called manually by Analyst. Pulls all `verifications` rows, logs a new `model_versions` row with incremented accuracy.

4. `generate_claim_pdf` — triggered when `claims.status` is updated to `APPROVED`. Generates Loss Assessment PDF, stores in `claims_reports/` bucket, updates `claims.report_url`.

5. `notify_farmers` — triggered on INSERT in `government_actions`. Looks up all farmers in the target district, sends push notification via FCM.

## CRITICAL IMPLEMENTATION NOTES

1. Every table update that matters to another role must flow through a realtime subscription — no polling.
2. All maps use Leaflet with dynamic import (no SSR) — `const Map = dynamic(() => import('../components/maps/ParcelMap'), { ssr: false })`
3. The chatbot FAB must appear on every dashboard page — put it in the dashboard layout, not individual pages.
4. Supabase client must be initialised with `createClientComponentClient` for client components and `createServerComponentClient` for server components.
5. RLS must be enabled on every table before deploying — never disable RLS for convenience.
6. PDF generation in Edge Functions uses `pdfkit` npm package compiled for Deno via `npm:pdfkit`.
7. Use `@tanstack/react-query` for all data fetching with proper cache invalidation on realtime events.
8. Toast notifications use `sonner` library with role-accent colour theming.
9. All monetary values display in Indian Rupee format: `₹{value.toLocaleString('en-IN')}`.
10. All dates display in IST (Indian Standard Time, UTC+5:30).

Build the complete application. Start with the database schema and seed, then authentication, then each role dashboard in order, then the chatbot, then Edge Functions. Every page must be fully functional, not a placeholder.
